# Contributing

Thank you for your interest in contributing to this project.

## How to Contribute

Contributions are welcome in the following areas:
- bug fixes
- compatibility improvements
- Blender workflow improvements
- import/export reliability
- documentation updates
- testing and validation with real game assets

If you want to contribute a larger change, please open an issue first so the idea, scope, and implementation approach can be discussed before work starts.

## Reporting Bugs

When reporting a bug, please include:
- Blender version
- plugin version
- operating system
- steps to reproduce
- expected behavior
- actual behavior
- relevant screenshots, logs, or sample files if possible

Clear and reproducible bug reports are much easier to investigate.

## Pull Requests

Before opening a pull request:
- make sure your changes are focused and relevant
- keep code changes as small and clear as possible
- update documentation if needed
- test your changes where possible

Pull requests should include:
- a short summary of the change
- the reason for the change
- any known limitations
- testing notes

## Coding Style

Please try to keep the code style consistent with the existing project.

General expectations:
- prefer readable and maintainable code over clever shortcuts
- avoid unnecessary refactors in unrelated areas
- keep function and variable names clear
- add comments only where they improve understanding

## Compatibility Notes

This project targets Blender-based modding workflows for *The Settlers: Heritage of Kings*.

When contributing, please be mindful of:
- Blender version compatibility
- import/export data integrity
- preserving existing file structures and game-relevant metadata
- avoiding regressions in working pipelines

## Testing

If possible, test changes with real project files before submitting.

Especially valuable are tests involving:
- DFF import/export
- JSON conversion consistency
- building animation import/export
- userdata, particle effects, and geometry handling

## Code of Conduct

Please keep discussions constructive and respectful.

## Questions

If you are unsure about a change, feel free to open an issue first and ask.
